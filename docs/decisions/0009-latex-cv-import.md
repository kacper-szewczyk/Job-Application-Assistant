# 0009 — LaTeX CV import and template candidates

- **Status:** Accepted
- **Date:** 2026-10-14
- **Issue:** #7

## Context
T06 imports LaTeX CVs (SPEC §4, §6, §7). It must produce reviewable facts and a list of recognized sections, report unsupported constructs rather than drop them, and let the source be registered as a template candidate for T08. SPEC §6 keeps the structured profile canonical: templates are render targets. ADR 0008 already has a heuristic CV parser (`parse_cv`) that works on located text lines, with stable field keys.

LaTeX CVs come in three common shapes: CV classes with semantic macros (moderncv's and awesome-cv's `\cventry`), plain `article` documents with sections, lists and tables, and templates built from the author's own `\newcommand`s (such as the widely copied "Jake's resume"). Many split the CV across files with `\input`.

## Decision
- **No TeX engine.** Running TeX would need an installed distribution (none is decided yet, T08), would run the user's macros with file and shell access, and would still only give us text. Instead, `jaa.importers.latex` has a small tokenizer and converter that turns the source into `SourceLine`s, and `parse_cv` makes the candidates, so field keys, confidence rules and issue reporting are the same as for PDF/DOCX.
- **What the converter understands:** sections (`\section`, `\cvsection`, …) become headings, list items become bullets, table cells and `\hfill` become ` | ` separators, formatting is dropped and its text kept, accents and symbols become Unicode, and `\href` gives its target in the header (contact links) and its label elsewhere. moderncv and awesome-cv personal-data macros (`\name`, `\email`, `\social[github]`, …) become header lines, and their entry macros pass named parts to the parser through `SourceLine.entry` (`EntryFields`: role, organization, dates, extras). These facts get confidence 0.8 instead of the heuristic split's 0.6–0.7. User `\newcommand`, `\def` with numbered parameters and `\newenvironment` are expanded, including definitions in local `.cls`/`.sty` files. Commands the importer knows keep their meaning even when the user redefines them, so a restyled `\section` still starts a section. Expansion is capped (5,000 expansions, 500,000 tokens), so recursive definitions stop with a warning.
- **Nothing is dropped silently.** Each of these becomes an `ImportIssue` with a location: unknown commands (their arguments are kept as text), unknown environments (content read as plain text; an unknown environment whose single argument is a known heading starts that section, e.g. `\begin{rSection}{Experience}`), skipped picture/figure/listing environments, images, unsupported definitions (delimited `\def`, `\NewDocumentCommand`), missing, refused or repeated includes, a guessed encoding, and a missing `\begin{document}`. Comments and `comment` environments are not content and are not reported. Named entry parts that are not imported (location, grade, unparsed date text) are reported by the parser. Preamble layout commands are ignored. The preamble stays in the template candidate.
- **Files.** The format is detected from the content: `\documentclass` or `\begin{document}`. A file with LaTeX markup but no `\documentclass` is refused, with advice to import the main file. `\input`, `\include`, `\subfile` and `\import` are followed only to `.tex` files that resolve, symlinks included, inside the main file's folder. That is at most 30 files and 25 MB in total. Files are read as UTF-8, falling back to Latin-1 with a warning. Locations are `line N` for the main file and `<relative path> line N` for the others.
- **Recognized sections** are recorded in `ImportRun.summary.headings` as `[{title, section}]` for every format, and the CLI prints them ("Sections: …; not imported: …").
- **Template candidates** are opt-in: `jaa import cv <file.tex> --as-template`. A new table `template_candidates` (migration 0004) stores a snapshot of the main file name and all project text files (`files`: `{relative path: source}`), the document class, the packages and a SHA-256 over the files. The same content is registered only once. Rows are immutable except `import_run_id`. Binary assets (photos, fonts) are not copied; T08 decides how a candidate becomes a template. The snapshot is stored in the database rather than as a reference to the user's path, so it survives the user moving or editing files and travels with export/backup.

## Consequences
- Plain-text extraction of arbitrary TeX is necessarily approximate. Heavily programmed classes may produce odd lines. The user sees these as unknown-command warnings and facts to reject, never as silent loss or confirmed values.
- `template_candidates.files` holds the whole CV source, including contact details. It is local, owner-only, included in exports, and must be covered by T19's deletion controls.
- The command vocabulary (`jaa.importers.latex_vocabulary`) is part of how existing CVs are read. Like ADR 0008's slug rules, changes to it need tests.
