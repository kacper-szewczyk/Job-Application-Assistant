# 0004 — Git workflow, Conventional Commits and automated releases

- **Status:** Accepted
- **Date:** 2026-10-14

## Decision
- One branch and PR per issue (`<type>/<issue>-<slug>`), PRs reference the issue and are squash-merged.
- Commit messages and PR titles follow Conventional Commits.
- Every behavior change ships with tests; CI runs ruff, pyright and pytest.
- Releases are generated by release-please from Conventional Commits on `main`: it maintains a release PR with the semver bump and `CHANGELOG.md`, and publishes a tagged GitHub release with release notes when that PR is merged.
- Significant decisions are recorded as ADRs in `docs/decisions/`.

## Consequences
- PR titles must be valid Conventional Commits (enforce with a CI check).
- Version numbers and the changelog are never edited by hand.
